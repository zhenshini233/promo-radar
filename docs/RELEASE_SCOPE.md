# 上线版范围（Release Scope v1.0）

> 目标：一次性推送时，系统在“数据可信、语义清晰、可回滚、可排障”四个维度达标。
> 原则：只做能改变结果的事；工程化按规模阈值触发，不提前铺。

---

## 1. 上线前必做（批次 A）

| # | 事项 | 为什么阻塞上线 | 验收 |
|---|---|---|---|
| A1 | **Offer 层**：促销活动从 deals 中结构化 ✅ | 现在“厂商 / 促销 / 证据”混在一起，用户看到的是原始条目 | `offers` + `offer_evidence` 两表；同一活动多渠道合并；活动能按 Provider 聚合 |
| A2 | **自动收编闸门** | aicredits 仍可能把非 AI 促销收进 watchlist | 新条目必须通过 AI 相关性 + 自助注册 + 非目录站检查；被拒条目有记录 |
| A3 | **32 条无官网核查** | 覆盖率缺口集中在 model_lab / unknown | 无官网条目降到 <10；每条有结论（官网 / 排除 / 保留观察） |

## 2. 上线前建议（批次 B）

| # | 事项 | 收益 | 验收 |
|---|---|---|---|
| B1 | **契约测试**：核心数据结构固定 | 防止重构破坏解析 | Deal / Offer / Provider 各一组 JSON 快照测试 |
| B2 | **基础可观测** | 线上出问题能定位 | 每次运行输出源级耗时/失败原因；连续失败进入健康摘要 |
| B3 | **回滚手册** | 出问题能退回 | data 分支保留上一版 DB；站点可重新发布 |

## 3. 上线后（批次 C，不在本次推送）

- SQLAlchemy / Alembic 迁移（条目上万再做）

- Scrapy
- LLM 逐条判定
